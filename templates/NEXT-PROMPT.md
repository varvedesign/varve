# NEXT-PROMPT template - one-seam handoff

This file is a **template**, not a handoff. The caller instantiates it into
`NEXT_PROMPT.md` at the repository root after a committed seam. The
instantiated handoff is a local, untracked artifact: it is not committed and it
is never validation evidence. The template is generic; instantiate it for any
next queue entry by filling placeholders only, never by editing the prose.

Caller rules:

- Fill every placeholder from the table at the bottom. Do not delete
  sections and do not add values that are not in the table.
- Never invent or copy a value. Counts in older handoffs, in `AGENTS.md`, and
  in the campaign plan are point-in-time and go stale; measure everything on the
  checkpoint the next session will use. If a value cannot be measured, record a
  blocker instead of guessing.
- Timestamps are generated by the caller (`date --iso-8601=seconds`); no
  wall-clock value is baked into this template and none is committed.
- Determine the next entry from the batch tables in the remediation doc and the
  campaign plan, crossed with the completed rows in `BACKLOG_LEDGER.md`.
- Keep the instantiated handoff near 120 lines. It points at policy; it does not
  duplicate it.

## Protocol (do not substitute)

1. Run the prompts in order: 01 research and gap analysis, 02 seam execution,
   then 03 and 04 only when their gates fire. Write the seam documents under
   `remediation/{{ENTRY_ID}}/` before touching source.
2. Work in `{{WORKTREE_PATH}}` on branch `{{BRANCH}}`, created from local
   `master` at {{CHECKPOINT_SHA}}. Never create it from `origin/main`: the
   remote does not contain the baseline, the guard scripts, the `audit:filesize`
   script, or the completed split batches, so the ratchet cannot run there and a
   PR cut from it would re-introduce god files that are already split locally.
3. Pre-flight in the clean worktree: `pnpm install --frozen-lockfile`;
   `pnpm audit:filesize` exit 0 at {{FROZEN_COUNT}} entries; `pnpm check:agent`
   exit 0; `node scripts/quality/godsplit-plan.mjs` on the target exits 0; and
   `node scripts/quality/refactor-verify.mjs --base master --target
   {{TARGET_FILE}} --json` exits 0. A missing tool or a red gate is a blocker.
4. Build the top-level declaration inventory with
   `node scripts/quality/godsplit-plan.mjs {{TARGET_FILE}} --top 200` (blocks,
   ranges, export status, first doc line, sub-split hazards), then read each
   block range and complete the inventory by hand in `SEAM_SPEC.md`. The
   planner is read-only and never proposes a destination; the seam is a review
   decision.
5. Move code only. Preserve comments verbatim, change no names, add no behavior,
   weaken no test. Keep every moved module under the 400-line cap (target
   350-400) and keep the target file shrinking.
6. Prove no declaration was dropped:
   `node scripts/quality/refactor-verify.mjs --base master --target
   {{TARGET_FILE}} --dest {{SEAM_DESTINATION}}`. Exit 0 is required before
   tests; a missing declaration or exported name means the cut is incomplete, so
   fix the extraction and never suppress the verifier.
7. Run the covering test before and after and record both counts; then
   `pnpm exec biome check --write <changed files>`,
   `pnpm exec biome check <changed files>`, and `pnpm check:agent`.
8. Ratchet the baseline once: `node scripts/quality/audit-file-size.mjs
   --update`, then `pnpm audit:filesize`. Exactly the intended entry must
   leave; no entry may be added or grown. `--update --force` is forbidden.
9. Stage the seam, then regenerate the repo map (`pnpm agent:map`) from the
   staged tree and run `pnpm verify:commit` (the staged-only commit
   checkpoint). Commit only the seam files, the baseline, the map, the ledger
   row, and the seam docs; no AI-tool attribution trailers.
10. Re-instantiate this template for the following unblocked entry with fresh
    measurements and write `NEXT_PROMPT.md`, then stop. Leave the branch for
    review; do not merge and do not prune the unmerged worktree.

## Repo-native command reference

| Command | Use |
|---------|-----|
| `pnpm audit:filesize` | file-size gate; must exit 0 before editing and after the split |
| `node scripts/quality/audit-file-size.mjs --report` | ranked inventory, excess lines, baseline count, WIP report |
| `node scripts/quality/audit-file-size.mjs --update` | rewrite the baseline after one intentional split; never `--force` |
| `node scripts/quality/audit-file-size.mjs --staged` | staged-blob check (also inside `pnpm verify:commit`) |
| `node scripts/quality/godsplit-plan.mjs <file> [--json] [--top N]` | top-level declaration blocks, line ranges, export status, sub-split hazards |
| `node scripts/quality/refactor-verify.mjs --base <git-ref> --target <path> --dest <dir> [--json]` | dropped-declaration and export-preservation proof for a code move |
| `pnpm check:agent` | quiet recursive TypeScript check; queued |
| `pnpm test:agent <spec>` | focused Vitest run; queued; pass the spec path, never the whole suite |
| `pnpm exec biome check --write <paths>` | format/lint fix on changed files; then check without `--write` |
| `pnpm agent:map` | regenerate `docs/agents/repo-map.generated.md` from the staged tree |
| `pnpm verify:commit` | staged-only pre-commit checkpoint (emoji, staged map, staged file size, health, docs, staged tests) |
| `pnpm audit:emoji`, `pnpm audit:docs`, `pnpm audit:imports` | cheap audits after touching docs, text, or imports |
| `pnpm audit:visual-baselines`, `pnpm visual:update --spec <spec> --project <project> --reason "<intent>"` | visual baseline audit and scoped update, only when a rendered surface changed |
| `pnpm worktree:status`, `pnpm queue:status` | concurrent-worktree state and validation-queue holder |
| `node scripts/quality/heavy-lease.mjs "<label>" -- <command>` | wrap any Playwright or other heavy browser/build run |
| `git worktree add {{WORKTREE_PATH}} -b {{BRANCH}} master` | create the task worktree from the local checkpoint |

Never run `pnpm build`, full Playwright, `cargo test --workspace`, or
`just gate` for a file split. Escalate only when the planner or the Lead says
to.

## Worktree, PR, ledger, and handoff rules

- One worker per worktree, one task per worker, one seam per task. Two writers
  never share a worktree.
- Generated and shared surfaces are single-writer: `.file-size-baseline.json`,
  `docs/agents/repo-map.generated.md`, `BACKLOG_LEDGER.md`, `docs/README.md`,
  `package.json`, lockfiles, and the dated remediation doc. Regenerate them;
  never hand-merge.
- Append exactly one row to `BACKLOG_LEDGER.md` for this seam with a
  caller-generated ISO-8601 timestamp. Do not edit the dated remediation record
  or the campaign plan; the orchestrator records merged seams there.
- Commit only the seam's source files, the target's covering test if its path
  changed, the baseline, the map, the ledger row, and
  `remediation/{{ENTRY_ID}}/` documents. `NEXT_PROMPT.md`, other sessions'
  files, lockfiles, and unrelated formatting stay out.
- PR only when the Lead explicitly authorizes a remote push and the remote base
  contains the checkpoint. Workers do not merge. Without authorization the
  branch stays local, committed and unmerged, for review.
- The handoff is regenerated from this template at the repo root, left
  untracked, and consumed by the next session. It must never contain a value
  that was not measured on the checkpoint tree.

## Do not

- Do not run `audit-file-size --update --force`, hand-edit
  `.file-size-baseline.json`, or freeze untracked WIP.
- Do not create the worktree or the PR from `origin/main`; it lacks the
  foundation commit.
- Do not change behavior, rename declarations, reformat unrelated code, add a
  feature, or weaken a test.
- Do not start a partial extraction: if the target stays frozen, the task
  scores as not done.
- Do not edit the dated remediation doc, the campaign plan, `docs/README.md`,
  or other single-writer surfaces.
- Do not commit `NEXT_PROMPT.md`, build output, screenshots, or another
  session's uncommitted work.
- Do not add AI-tool attribution or co-author trailers to the commit.
- Do not start the next seam, merge, prune the unmerged worktree, or push
  without authorization.
- Do not copy stale counts or invent timestamps; measure, and cite the command.

## Stop rule

Stop after one seam. The task is done only when all of the following hold: the
branch `{{BRANCH}}` carries one commit containing the seam; the covering test
count is unchanged; `refactor-verify` passed; `.file-size-baseline.json` has
exactly one fewer entry and no added or grown entry; `BACKLOG_LEDGER.md` has
one new row; and `NEXT_PROMPT.md` has been regenerated for the following
entry. Do not open the following entry in this session, even if it is already
unblocked.
