# Design-to-code gap research ledger

Checked 2026-10-15/16 against live sources where reachable. Format:
source → finding/complaint → applicable risk → decision → acceptance
evidence. The ledger is the "what failed elsewhere" record behind
`docs/architecture/code-export-system.md`; do not mistake an external
complaint for a reproduced Varve defect (each risk row names the local
reproduction).

## External issue trackers

**FigmaToCode #157 — "HTML output not responsive"** (opened 2025-01-13 by
mimshwright, closed 2025-03-18 via PR #184). Fill/Hug sizing exported as
fixed pixels; the owner noted the fix required emitting the flex properties
that make `100%` meaningful, and admitted the plugin "predates the
responsiveness features". → Risk: sizing-mode emission without the layout
context that gives it meaning. → Decision: sizing modes are emitted only
relative to their authored parent layout context; a fluid no-breakpoint
corpus document (responsive-page) must export with `flex` behavior, not
pixel widths. → Evidence: `packages/codegen/src/css.ts` flow-item sizing;
corpus test asserting authored auto-layout exports as flow.

**FigmaToCode #116 — "Better Responsive Preview"** (opened 2024-07-13 by
davestewart, still open as of the last check). The built-in preview was
HTML-only and could not render Tailwind; maintainer response: "I don't know
how to support Tailwind, hence HTML-only"; participants asked for real
per-target previews or none. → Risk: a preview that transforms the output
into something else teaches users nothing about the deliverable. →
Decision: preview only the targets a browser renders without a runtime
(SVG, HTML), render the generated bytes in a locked sandbox iframe, and
disclose "download and build" for everything else. → Evidence:
`packages/editor/src/components/SpecPanel/preview.ts`; Preview pane in
CodeGenView; E2E sandbox assertions.

**figcraft #467 — import gives no warning when it silently drops data**.
→ Risk (universal): silent omission anywhere in a fidelity pipeline.
→ Decision: every lossy lowering must surface as a node-attributable
diagnostic; missing raster fallbacks fail the export job
(`assertRasterCompositionComplete`); unmeasured SVG text is disclosed in
the file itself. → Evidence: exportService fail-loud path; svg disclosure
comment test.

**figcraft #464 — .fig import silently drops instance-swap overrides.**
→ Risk: component instances exporting as frozen clones without their
authored overrides. → Decision (designed, open workstream): component
extraction must resolve the variant/override effective overlay before
conversion. Scene machinery exists (`packages/scene/src/component.ts`,
`variant-apply.ts`); IR population is the remaining work.

**figcraft #465 — grid auto-layout loses tracks so layout collapses on
first edit.** → Risk: authored grid structure lost in translation. →
Evidence handled: `css.ts` emits authored `grid-template-columns/rows` and
separate row/column gaps (negative gaps clamp with a disclosed TargetGap).

**figcraft #466 / #460 — text properties dropped; reimport shifts spacing.**
→ Risk: rich text fidelity through conversion boundaries. → Decision +
evidence: `rich-text.test.ts` (paragraph boundaries, run color/italic/
decoration/case, blank paragraphs, RTL direction) across HTML, Tailwind,
CSS Modules, Flutter (`Text.rich`), SwiftUI (concatenated `Text`), and
measured SVG runs.

**figcraft #473 — Dart/Flutter export requested.** Context for keeping the
Flutter target first-class but honestly gated (`verify-flutter.mjs`).

## Platform and standard anchors

**Figma Code Connect** (developers.figma.com/docs/code-connect/): explicit,
typed design-to-production component mappings as data, validated by the
tooling. → Decision: Varve's mapping contract (when built) is validated
data — import specifier, export name, property map — never name-guessed,
never executed.

**Plasmic codegen-components** (docs.plasmic.app/learn/codegen-components/):
generated versus developer-owned separation. → Decision: regeneration
ownership via the manifest + planner; unchanged generated files update,
edited files conflict, unclaimed files are preserved.

**W3C CSS Flexbox / Compositing & Blending** (css-flexbox-1,
compositing-1): blend correctness depends on the backdrop; a blended leaf
rasterized alone can be wrong. → Decision: raster boundaries are the
compositor's smallest isolating subtree, chosen by capability tables, not
mechanically the leaf.

**MDN box-shadow / conic-gradient**: inset shadows and conic gradients are
native CSS with well-defined semantics. → Decision: emit natively when
geometry matches (rect/radius for inset; renderer-derived `from` angle and
center for conic), raster when unproven. → Evidence: bundle-assets.test.ts
CSS lowering cases.

**W3C SVG 2 text** (SVG2 text.html): the spec defines wrapping, but no
browser ships it; `textLength` squeezing is a recognized anti-pattern.
→ Decision: measured placement profile (engine layout baked into tspan
geometry); no `foreignObject`, no auto-wrap, no `textLength`. → Evidence:
`svg-measured-text.test.ts` parity with `buildTextLayoutSnapshot`.

**MDN iframe sandbox + Tauri capabilities**: `allow-scripts` +
`allow-same-origin` together defeats the sandbox; opaque origins report
`null` origin and must not be blanket-trusted. → Decision: `sandbox=""`,
srcDoc-only, no messaging; desktop IPC non-exposure documented as a
configuration contract.

**Tailwind source detection** (tailwindcss.com/docs/detecting-classes-in-
source-files): dynamically constructed class names are invisible to the
scanner. → Decision: all emitted utilities are complete literal strings.
→ Evidence: the real-toolchain harness produced 8 KB of CSS including the
emitted conic/linear arbitrary utilities (2026-10-16 run).

**Node --enable-source-maps** (nodejs.org/api/cli): named in early
discussions as if it could "verify" Flutter/SwiftUI; it improves JS stack
traces and compiles nothing. → Decision: verification gates are named by
what they execute; native targets report UNVERIFIED (exit 2) without their
SDKs rather than passing by parser.

## Community complaints (general knowledge; searches rate-limited at
research time, so these are the long-standing recurring criticisms of
Figma-to-code tooling — Locofy/Anima-class output — commonly reported on
Hacker News and r/reactjs)

1. **Absolute-positioning soup** — everything exported as fixed x/y.
   Varve: authored auto-layout exports as flow; freeform stays honestly
   absolute (it is freeform).
2. **Unmaintainable class soup / div-per-layer** — no semantics, no
   components. Varve: semantic hints in HTML; component extraction is the
   designed open workstream (scene machinery exists).
3. **Non-responsive px output** — see FigmaToCode #157; fluid corpus covers
   the no-breakpoint case; authored conditions are the designed open
   workstream.
4. **Preview that lies** — see FigmaToCode #116; disclosure-first preview.
5. **Asset leakage** — blob/dev-server URLs in shipped code. Varve:
   `unstableImageSourceReason` errors plus the harness's portability scan;
   bundles are content-addressed files.
