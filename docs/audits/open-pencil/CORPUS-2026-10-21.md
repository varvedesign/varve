## Implemented in this review

### #186 — a control gesture is one undo step

Drag a slider or colour picker, or hold an arrow key, and the document is
written once per event. With no open transaction each write pushed its own undo
entry: `Ctrl+Z` stepped back one intermediate value, and a single drag could
consume the 50-entry history window.

Varve had this defect live in three places and latent in two more:

- `setMaskDensity` and `setSelectedCornerSmoothing` reached `updateDoc` with no
  transaction at all.
- The floating text bar's colour picker was never wired to the preview
  transaction the bar already exposes.
- `ColorPicker` treated only pointer input as a gesture, so keyboard stepping in
  every host (fill, stroke, typography, selection colours, effect popovers)
  pushed one entry per keypress.

`context/useGestureTransaction` is now the single mechanism: one transaction per
gesture, pointer capture so a release outside the control stays in the gesture,
window-level `keyup`/`blur` and an unmount commit so a transaction is never
stranded open, Escape aborts. The boundary is gesture-based, not time-based, so
two deliberate quick edits are not fused. ADR-0198 gains D5.

Evidence: `89880889b`; `useGestureTransaction.test.tsx` (14 tests) plus
component tests for mask density, corner smoothing, the text-bar picker, and the
`ColorPicker` primitive. Each regression test was re-run against the previous
wiring and fails there.

### #698 — one authority for unsaved work

`state.dirty` and `sessions[activeId].dirty` describe one fact and are read by
different surfaces. The tab strip and save-status affordance read the state
flag; the tab close guard (`closeTab`) and the termination coordinator
(`collectUnsavedDocuments`) read the session flag. Several mutation helpers set
only the state flag, so a real edit could look saved to the path that decides
whether work may be destroyed: the tab closed or the app quit with no prompt,
and the recovery point was deleted on the resulting clean shutdown.

`useLogoGeometry` was the live vector — it writes the document from its own
setter with no transaction around it, so nothing repaired its bookkeeping. The
group/ungroup, boolean, clipping-mask and paste sites were latent: they run
inside a transaction whose commit already synced the session flag.

`markDocumentDirty` is now the single write path, `setDocumentState` applies it
to mutations that own their setter, and one reconciliation guard catches any
hand-written site that remains. It only ever adds dirtiness the state already
claims, so it cannot mark a saved document dirty.

Evidence: `13014f0ed`; `unsavedWorkAuthority.test.tsx` proves the stale-state
shape yields zero documents for `collectUnsavedDocuments` and that the authority
repairs it.

### #503 — seeded system fonts are verified against the device

The registry seeds common system families (`Arial`, `Helvetica`, `Meiryo`,
`Noto Sans CJK`, …) so a fresh document resolves something, and
`availableFamilies()` projected that registered map directly. The seeds are
claims about the host, not evidence. On a machine without one, the canvas drew
the CSS fallback while preflight, the Missing Fonts dialog, and the export
preflight reported the typography as faithful.

`document.fonts.check()` cannot detect this. Measured in Chromium on
2026-10-21, a deliberately nonexistent family reports `true`: the API reports a
pending load for a *declared* face and otherwise has nothing to say about
host-installed families. On this host it reported `true` for every candidate,
including `Meiryo` and an absurd sentinel, while width measurement correctly
separated present from absent.

`font/systemFontProbe.ts` measures instead. An unknown family contributes no
glyphs, so `"<family>", <generic>` is exactly as wide as `<generic>` alone; a
family counts as resolved when any of the three generic fallbacks differs. That
direction is the safe one — a real font yields one width and the three baselines
are three distinct widths, so a metric coincidence cannot mark a real font
missing, which is the failure users notice.

Scope is deliberately narrow: only `DEFAULT_FONTS` entries with
`source: 'system'` are probed. Bundled faces ship with the app, and a family
that arrives from real enumeration was observed on the host. A spurious dialog
on every open would be worse than the bug. When the environment cannot shape
text the probe answers `unknown` and every family stays available.

Evidence: `16daae2f4`; `systemFontProbe.test.ts`, `fontRegistry.test.ts`,
`fontBridge.test.ts` (including `detectMissing` classifying the family as
`missing-family`), and `tests/e2e/canvas/font-availability.spec.ts`, which
imports a document typeset in `Meiryo` and asserts the dialog appears. The E2E
was re-run with the probe disabled and fails there. The captured dialog was
inspected: it names `Meiryo`, "Missing family", the affected node count, and
offers a replacement.

### #48 / #291 / #346 — CJK fallback is the same gap

Complaints that CJK text renders as boxes or "NO GLYPH" even with a
"supported" font installed are the availability gap above when the requested
family is a seed this host lacks. Those are now reported rather than rendered
silently. #291 additionally needs glyph-range coverage, which Varve only checks
when a face publishes unicode ranges — registry-projected seeds do not — so that
part is recorded as an open gap rather than claimed fixed.

## Verified as already correct (no change made)

Each of these was a source-only candidate in the prior ledger and is now
resolved with evidence in the code rather than left as a suspicion:

- **#145 / #142 / #220 (Backspace deletes the node while editing text).**
  Structurally impossible in Varve: in-canvas text editing is a native
  `<textarea>` overlay, and `shouldIgnoreShortcutTarget` suppresses global
  shortcuts for textarea targets. The other application's canvas-drawn editor
  was the cause.
- **#200 / #169 (deleting text in a field removes the node).** Inspector fields
  and the layers rename input are native form controls, which the shortcut
  target guard excludes before any tree-item delegation.
- **#28 / #1035 (shadow under a fully transparent fill).** Varve casts shadows
  from the item's true alpha silhouette whenever a fill is partially or fully
  transparent, so a 0 % fill produces an empty silhouette and no shadow.
- **#168 (children's hover area wrong after rotating the container).** Varve hit
  tests by inverting each node's own composed affine transform, so rotation is
  part of the test rather than an axis-aligned approximation.
- **#79 (paste at the pointer).** Placement is centralised in
  `resolvePasteDestination` and every normal paste entry point reaches it;
  container-targeted paste is implemented. The two "paste special" handlers
  re-derive the destination policy by hand instead of calling the helper — a
  drift risk recorded in the ledger, not a current defect.
- **#87 (IME).** An active composition owns keyboard input, with a
  visible-composition fallback for Linux/IBus.
- **#181 (Enter does not set a typed value).** The inspector numeric field
  commits on Enter and blur and coalesces keyboard bursts.
- **#131 (optical-size suffixes reported as missing fonts).** Varve models
  optical size as a real `fvar` axis and resolves families through the registry
  rather than matching raw name suffixes.
- **#229 (persistent font cache).** Stored faces are restored at startup.

## Limitations of this review

- Attachments, external Figma archives, recordings and reproduction bundles
  referenced by issues were not retrieved. Links were followed only where they
  carried the failure mechanism (largely comment threads from maintainers who
  identified the root cause).
- Linked pull-request diffs were not exhaustively inspected, so a fix claimed in
  a PR is not treated as evidence that a shipped build behaves that way.
- **WebKitGTK is unverified.** Playwright WebKit cannot launch on this host
  (missing `libicu74`, `libxml2`, `libflite1`) and installing system packages was
  not authorised, so the desktop webview's probe behaviour is unknown. If that
  engine resolves an unknown family to the default face for every generic, the
  probe reports it present — a false negative that preserves the old behaviour
  rather than inventing a wrong warning. The durable fix is to verify the seed
  list against `enumerate_system_fonts` on first document open; not implemented.
- The browser runs logged a failed WASM load and fell back to the pure-TS stub
  renderer, which was already the case before these changes. The captured
  evidence certifies the editor UI, font resolution and the Missing Fonts
  dialog; it does **not** certify the WASM renderer.
- Browser evidence does not certify the native Tauri path, and no native desktop
  build was produced in this pass.
