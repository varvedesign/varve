# tldraw issue review: positions 1801–1850

Reviewed 50 issues (#7009–#7437) and all 182 retrievable comments. Assessment
records are in `../assessments/range-1801-1850.jsonl`; the frozen source and
comment cache remain outside Git.

## Findings

- The batch includes upstream-resolved issues for frame paste (#7214), Android
  low-pressure drawing (#7203), compressed ink (#7101, #7371), arrowheads
  (#7422), and culling (#7425). Those upstream resolutions do not establish
  equivalent behavior in Varve.
- #7203 documents a concrete touch-pressure edge case: some Android hardware
  reports a very small non-zero finger pressure that upstream once classified
  as stylus input. Varve has not been reproduced on that hardware; retain it as
  a browser-input test lead before changing pressure normalization.
- #7072 records a deliberate 200-point stroke segmentation threshold, with
  upstream reconsidering it after storage changes. The reported selection
  difficulty is a trade-off to measure, not proof that segmentation is a bug.
- Open feature and investigation requests include per-shape-type style
  persistence (#7019), global multi-page text search (#7426), and frame-like
  resizing behavior (#7176). They remain product follow-ups; this batch did not
  reproduce a Varve defect that justified a change.
- Several reports are integration guidance or environment-specific: page
  annotation and lightbox examples (#7011, #7340), missing self-hosted download
  menu (#7059), the third-party LegendKeeper validation error (#7427), and the
  local database-reset report for tldraw's sync worker (#7078). The 11 repeated
  generated proposals in #7078 do not constitute maintainer confirmation.
- The remaining discussions clarify already-available behavior, identify
  upstream fixes, or lack enough reproduction evidence. Every issue remains
  individually represented in the ledger, including empty and stale records.

## Validation

No Varve implementation change was made from this issue batch. The 50
assessments were imported atomically into the issue ledger after checking each
body and every retrievable comment. `pnpm audit:docs` is run for this report
and its README index entry; implementation validation is tracked in the
current engineering checkpoint because its affected browser lane is still in
progress.
