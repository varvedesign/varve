# tldraw issue review: positions 1901–1950

Reviewed 50 issues (#7489–#7575) and all 142 retrievable comments. Individual
assessments are in `../assessments/range-1901-1950.jsonl`.

## Findings

- Most entries request SDK examples or developer documentation for binding,
  rendering, camera, accessibility, localization, input, and configuration
  APIs. Stale-bot closure is not treated as evidence that an example shipped.
- Several actual upstream changes are recorded separately: RTL list layout
  (#7497), accessibility examples (#7501, #7503), zoom-to-fit padding (#7515),
  reduced-pressure draw storage (#7556), dependent-app publishing (#7565),
  and the TypeScript native compiler migration (#7574).
- #7557 is an upstream-confirmed pinch/editing concern. The discussion notes
  that replacing its never-set editing flag can break pinch lifecycle setup;
  it has no final resolution. No Varve pinch reproduction was run.
- #7545 describes a concrete pattern-fill scale mismatch and a proposed fix,
  but has no recorded resolution. Varve rendering has not been checked for the
  same visual defect; keep it as a candidate for source inspection and visual
  comparison before implementation.
- Other notable unresolved or contextual findings include frame-descendant
  snapping (#7499), cloning arrow bindings (#7528), transparent-image
  hit-testing (#7529), native clipboard policy (#7547), and the dark-mode
  startup/CSP trade-off (#7542). None was reproduced in Varve in this batch.
- The reports on mobile color scrubbing (#7559) explicitly say scrubbing is
  intentionally disabled for coarse pointers and separate mobile scrolling
  behavior into another issue. The groups admin access toggle (#7570) is tied
  to a data migration and cannot be treated as a simple flag flip.

## Validation

The 50 assessments were imported atomically after reviewing each issue body
and all retrievable comments. `pnpm audit:docs` is run for the report, ledger,
and README index changes. No application tests were selected by this
documentation-only batch; implementation validation remains tracked in the
engineering checkpoint.
